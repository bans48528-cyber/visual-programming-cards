# 自学习口令积木：手机、PY32、ASRPRO 对接契约

版本：1.0（2026-10-20），软件实现与实机验收状态见文末。本功能独立于固定词条等待 `0x51`。

## 1. 分工与上线前提

- 手机负责作品编辑和程序执行；本轮手机由用户安排同步开发。
- PY32 负责蓝牙会话、安全互斥、任务关联、将真实语音事件转发给手机。
- ASRPRO 负责原厂自学习、逐遍录入、模板保存和识别。
- 现有 HD/普通语音协议不能假定支持本功能。手机须订阅 D2/D3、进入编程模式、保持现有 300ms 心跳，并查询能力。
- 进入编程模式后立即保持心跳；收到模式事件后可留约 250ms 稳定窗口，再用 `QUERY_STATUS (0x04)` 确认 mode=4，然后查询十槽。延时本身不代表进入成功。只读查询超时可有限重试，仍失败则显示状态未知；不要因此重发旧协议的非幂等动作。实机曾出现进入后首条状态查询无回复，留窗口后查询成功，具体丢帧原因尚未确认。
- 未连接允许编辑作品，不允许学习或运行。设备未返回完整能力时显示“设备暂不支持自学习口令”，不能使用计时动画假装学习。
- ASR 原厂 `cwsl_sample` 已开启一个唤醒词槽及十个命令词槽，命令槽 1..10 对应原厂 ID 10302..10311。固定识别词条 42..51、唤醒词 ID 0/10300 不改变。

## 2. 公共编码

沿用 17 字节 BLE 帧：`5A SRC DST 0A TYPE DATA[10] SUM A5`。
App→设备 `SRC=97 DST=98`，设备→App 反向；`SUM` 为前 15 字节之和的低 8 位。
十六进制帧类型 C2 请求、D2 响应、D3 异步通知。所有多字节整数为 little-endian。

- C2 DATA = `[seq, opcode, args(8)]`。
- D2 DATA = `[seq, opcode, result, data(7)]`。
- D3 DATA = `[event, eventCounter, data(8)]`。
- `seq` 和 `eventCounter` 只有 8 位，不能作为长期任务标识。
- 同 task 的请求重发保留原 seq；手机以 task 关联 D2/D3，不依赖改变 seq 来替换正在准备中的请求。
- `task` 为非零 uint32，学习/等待共用编号空间。手机按设备持久递增生成，跨作品、停止、断连和 App 重启均不复用。达到上限时禁止继续复用编号，重新建立安全会话方案后才能运行。
- `qid` 为查询编号，独立于学习/等待编号；每次查询使用新编号，迟到的旧查询不得覆盖当前查询状态。
- 同一任务重发不能重复录制、重新启动等待或重复推进程序。同编号参数冲突必须拒绝。
- 同 task、同参数重发时，设备重发缓存的受理响应及最近阶段／终态／命中；终态后不得重新录制或重新布置等待。缓存被更新任务替代后，旧任务重发返回任务冲突，不当新任务执行。
- 若等待 D2 已受理、约1秒仍未收到 stage11，同一连接内可按相同 seq/task/slot 有限重发原等待请求（建议最多2次）。主控只回放最新状态，不重启任务、不延长超时；若回放终态则按终态结束，不能猜测已就绪。这个机制不能补回所有历史进度，也不能跨重连恢复旧任务。
- 未确认 stage11 时若仅收到缓存 HIT，不把它补作已就绪证明并推进程序；保守终止本次等待，避免混淆当前状态与丢失的历史事件。
- 未使用字节必须填零。
- 新连接或芯片重启后不能恢复旧学习/等待。手机不恢复旧运行，也不重发上一连接任务；先建立编程会话、重新查询能力和状态，再用新编号操作。缓存重发只用于同一次有效连接和会话内的当前/最近任务。
- 本版没有 ASR 启动代号握手。ASR 单独重启会丢弃其任务，主控通过通信异常或现有任务超时结束等待，不能承诺立刻发现 ASR 重启；PY32 重启／蓝牙断连则按连接失效结束手机程序。
- 学习或重学到达终态后，手机作废该操作之前尚未完成的状态查询；迟到的旧 qid 响应不能覆盖终态状态。若需要完整十槽状态，发新的查询。

## 3. 请求与响应

| 操作码 | 用途 | C2 args[8] | 成功 D2 data[7] |
|---|---|---|---|
| 0x52 | 查询全部十槽状态与能力 | qid[4], 0,0,0,0 | qid[4], mask[2], caps |
| 0x53 | 学习指定位置 | task[4], slot, replace, 0,0 | task[4], slot, state, 0 |
| 0x54 | 取消当前学习 | task[4], 0,0,0,0 | task[4], slot, state, 0 |
| 0x55 | 等待指定已学口令 | task[4], slot, 0,0,0 | task[4], slot, state, 0 |
| 0x56 | 读取设备稳定标识 | part, 0,0,0,0,0,0,0 | part, uidBytes[6] |
| 0x57 | 程序运行声明 | runId[4], active, 0,0,0 | runId[4], active, 0,0 |
| 0x05 | 停止程序及当前学习/等待 | 沿用现有格式 | 沿用现有格式 |

`slot=1..10`；`replace=0` 仅允许未学习位置，`replace=1` 允许替换旧口令，也允许学习空位置。
`state=0` 未学习、`1` 已学习、`2` 状态未知。
`mask` 的 bit0..bit9 分别对应指令1..10，bit10..15 必须为零。只有查询 result=0 且能力满足时才能把位图用作“未学习/已学习”。

手机通过运行前检查后，先发送 0x57 `active=1`，等待受理，再开始执行积木。
`runId` 非零且每次运行递增，手机按设备持久保存，用于匹配当前运行，独立于各积木的 task。
运行声明持续覆盖积木之间的空隙：即使当前没有等待任务，主控也拒绝学习请求。
正常程序结束发送同 runId 的 `active=0`；主控停止电机并结束尚未退出的相关任务。
停止程序、断连、心跳丢失或模式退出自动清除此运行声明。0x55 要求当前运行声明有效。
当前运行的重复开始只确认，不重新执行；结束后的旧开始请求拒绝。重复结束不会取消后来开始的学习任务。
旧固定词条及既有动作操作码继续兼容旧手机；新手机应统一使用运行声明，不能仅靠 UI 按钮互斥。

`caps`：bit0 指定单槽学习；bit1 真实逐遍事件；bit2 保存确认；bit3 任务关联等待。
本功能要求 `(caps & 0x0F)==0x0F`；未安装语音桥接的 HD 返回能力 0，不能假报支持。
查询必须刷新 ASR 状态；超时不能把零位图当“全部未学习”。
保存确认必须来自非易失存储完成和有效模板读回校验。仅有 RAM 模板计数或“第二遍结束”回调不能作为阶段4证据。

0x56 的 part=0/1，分别返回芯片 UID96 的前/后 6 字节，按 part 顺序拼成 12 字节，再逐字节转成 24 位十六进制字符串。手机备忘键使用 `xiaobai:<UID96>:<slot>`，不可用显示名称或短期蓝牙扫描索引代替稳定标识。

result：

| 值 | 含义 |
|---|---|
| 0 | 成功／请求已受理，**不等于学习成功或等待命中** |
| 1 | 参数非法 |
| 2 | 未支持操作码 |
| 3 | 模式错误 |
| 4 | 忙碌，学习与程序执行互斥 |
| 5 | 指定位置未学习 |
| 6 | 指定位置已有口令，须明确重学 |
| 7 | 任务编号冲突或过期 |
| 8 | ASR 不支持所需能力 |
| 9 | ASR 无响应／查询状态未知 |

## 4. 设备事件

D3 `event=0x08`，data=`[task(4), slot, stage, state, reason]`。

| stage | 含义 | 手机处理 |
|---|---|---|
| 0 | ASR 接受任务 | 保持学习中，不标已学 |
| 1 | 原厂提示已结束，第一遍录制请求已成功提交 | 显示“请说第一遍” |
| 2 | 原厂确认第一遍有效 | 显示“第一遍已收到” |
| 3 | 原厂提示已结束，第二遍录制请求已成功提交 | 显示“请再说一遍” |
| 4 | 模板保存已验证成功 | 更新为已学习，且只弹一次文字备忘输入 |
| 5 | 失败 | 按 state 更新，提供重试／返回 |
| 6 | 超时 | 按 state 更新，提供重试／返回 |
| 7 | 取消 | 按 state 更新并结束弹窗，不推进程序 |
| 8 | ASR 拒绝任务 | 显示原因，不标已学 |
| 9 | 从第一遍重新录入 | 清除首遍有效标记，等待下一次stage1录制请求就绪事件 |
| 10 | 第二遍需重试 | 保持学习中，等待下一次stage3录制请求就绪事件 |
| 11 | 等待识别已准备好 | 当前等待任务进入已就绪状态，仍不推进程序 |

学习终态为 4..8；终态的 state 必须来自设备重新查询结果。无法确认则为 2，不能猜旧模板保留或消失。
重复阶段通知允许重复接收，但不得重复打开弹窗；终态按 task 只消费一次。

**原厂进度边界（实机勘误）：**本版 SDK 的示例 `on_cwsl_record_start` 并未被实际识别库调用，不能作为检测到说话的证据。修正版 stage1/3 来自可达的原厂提示音完成回调，且仅在原厂录制请求成功入队后发出；这是“请说第N遍”的真实流程进度，不表示已经检测到声音或收到了有效录音。
手机收到受理后显示“请跟随小白语音提示”；收到 stage1 才显示“请说第一遍”。
收到 stage2 显示“第一遍已收到”，收到 stage3 再显示“请再说一遍”。
不通过定时器把“准备中”升级为已检测说话、录制有效或保存成功。
原厂第二遍比较不匹配会从第一遍重新录制，发 stage9；第二遍过短等仍可重试第二遍的情况发 stage10。
若需精确显示“已经检测到用户说话”，仍需原厂开放可达的VAD事件；本版本不伪造该事件。

D3 `event=0x09` 命中：data=`[task(4), slot, 0,0,0]`。
只接受当前已就绪等待任务的相同 task 和 slot；消费后立即标记完成，重复命中不能推进下一块。
下一块即使等待同一 slot，也必须发送新 task，等待新的语音识别，不能复用上一条识别结果。

reason：0 无；1 模式；2 忙碌；3 位置非法；4 未学；5 已学；
6 取消；7 超时；8 ASR 不可用；9 保存或删除失败；10 协议错误。

App 主动发送 0x05 时，本地立即结束程序，沿用旧协议不等待 0x05 回包；设备结束相关学习/等待。
断连、心跳丢失、模式切换和语音停止通过 PROGRAM_ABORT 结束程序；不能转换成正常命中。
PROGRAM_ABORT 既有 reason=1 心跳、2 断连、3 按键、4 App 切模式保留；新增 5 语音停止、6 ASR 异常或等待超时。
data0 为 reason、data1 仍为目标模式，兼容既有手机；本次新增中止路径还在 data2..5 附带 task、data6 为 slot、data7 为任务类型。手机结束程序应以 reason 为准，不要求旧路径填充附加字段。
主控仍遵守现有心跳超时约 1000ms，不等待手机取消请求才刹停。

手机查询等待上限建议 2 秒，主控查询 ASR 超时为 1.5 秒；可以用新 qid 重试。
新学习／等待任务最多准备 8 秒，以等上一条退出唤醒和音频真正结束；此时继续心跳，不标记已就绪。
学习／等待首次受理响应建议等待10～11秒以覆盖准备期，不能套用只读查询的2秒时限。
受理后的学习／等待上限为 60 秒，取消确认上限为 3 秒。超时后以设备终态为准；无法读到状态时保持“未知”并重新查询。

## 5. PY32 ↔ ASRPRO 扩展

ASCII 十进制，主控以 LF 结尾，语音端以 CRLF 结尾，保留原 `play`、`cmd`、`wakeup`、`sleep`、`learn` 协议。

| 方向 | 帧 |
|---|---|
| 主控→ASR | `cq=<qid>` |
| 主控→ASR | `cl=<task>,<slot>,<replace>` |
| 主控→ASR | `cc=<task>` |
| 主控→ASR | `cw=<task>,<slot>` |
| 主控→ASR | `cx=<task>` 取消当前等待 |
| ASR→主控 | `cs=<qid>,<mask>,<caps>` |
| ASR→主控 | `ce=<task>,<slot>,<stage>,<state>,<reason>` |
| ASR→主控 | `ch=<task>,<slot>` |

单帧含结尾不超过 40 字节。非法数字、溢出、缺字段、多字段、非法槽号或阶段值拒绝，禁止将坏帧截成合法任务。
查询可由主控启动时内部触发；手机请求仍需编程会话。学习和等待仅在 mode=4 接受。
UART 查询编号 0 保留给主控开机内部查询，手机必须使用非零 qid。
开机内部查询每 3 秒尝试一次，最多 3 次；收到有效状态或不支持能力后停止。手机查询优先。
UART `cs` 的 caps bit7 表示“存储状态校验失败”：此时 mask 无效，主控清除已知状态并向手机返回 result=9；
未安装桥接的 caps=0 表示不支持，不能混作已查询到十槽全空。手机正常能力响应只使用低四位。
自动准备唤醒状态；模式退出/停止时清除任务，不能把语音模式的唤醒学习状态混入编程命令槽状态。
编程命令槽命中只上报当前任务，不复述口令，也不执行语音模式动作。原厂学习提示与程序显式播放音频保持有效。
“停止、停下、暂停”均作为停止处理，不能视为任一学习口令等待命中。

## 6. 手机交互验收清单

1. 进入编程界面统一查询，十槽先显示“读取中”，查询成功后才改已学/未学，失败为“状态未知”；重连重新查询。
2. 未连接可编辑。学习、运行前要求连接、反馈订阅、编程模式、心跳及能力完整。
3. 未学点击后创建新 task，弹窗阶段仅跟随真实设备事件，首遍有效不等于保存。
4. 学习成功后填写备忘，可空；空值显示“指令N”。备注不发送给设备、不用于识别。
5. 已学口令可只改备忘。重学前提示“所有使用这个指令编号的积木和作品都会使用新口令。”
6. 删除积木不删设备口令；UI 不提供清除命令词按钮。
7. 运行前检查本作品引用位置，未知则查询，未学则定位对应积木并阻止运行。
8. 运行中禁学习、重学、切换编号。学习中禁运行，每台设备仅一个学习任务。
9. 命中匹配 task/slot 后才执行下一块；旧任务、其他口令、重复反馈、学习语音都不推进。
10. 停止、断连、心跳异常、模式切换结束程序；重连不自动续跑。

## 7. 交付与验证状态

本契约用于手机同步开发；手机尚未实现不能计为验收通过。
仅靠现有 HD 无法获得真实逐遍进度。原厂应用层需最小桥接，提供指定单槽操作、真实录入事件和保存验证；不修改闭源识别库或编译下载工具。
扩展文件与安装差异先在仓库交付；用户于 2026-10-20 明确批准后，本机已安装两处原厂应用扩展及两个头文件。
用户已确认更新 ASRPRO；主控已烧录并通过基础冷启动确认。电脑蓝牙实测可查询十槽，指令1的两遍学习保存及新查询位图确认通过。
v1.4 实机仅返回学习阶段0/2/4，缺少阶段1/3。实际原厂 ELF 证明此前接入的录音开始、VAD及识别成功示例回调未被调用。本次v1.4.1已改用真实提示完成及decoder入口，并在已安装源码的完整诊断ELF中确认13条必要路径可达；设备尚待用户重新烧录、实机复测，不能仅凭能力0x0F宣告完整支持。

手机对接可直接使用同目录的 `learned_command_vectors.json`，其中包含完整帧、校验和与对应串口消息；示例 UID 是虚构测试数据。
不要仅更新主控就开放手机学习按钮：旧语音固件或未安装桥接时，能力不足必须阻止学习和运行自学习积木。

必须分别完成软件测试与实机验收：正常学习、首遍无效、第二遍重试、取消、重学成功与失败、
断连重连、冷启动保存、备忘独立修改、未学习阻止运行、其他口令不推进、重复反馈不重复执行、
连续两块同槽等待需要两次新识别。状态为“待验证”的项目不得以模拟测试替代实测。

### 联调顺序与证据

1. 先安装经版本校验的语音应用扩展，再由用户重新生成十个命令槽的模型及提示音、正常编译和烧录 ASRPRO；更新配套 PY32。两芯片版本未配套时不进入正式验收。
2. 手机建立连接和通知订阅、进入编程模式、持续心跳，读取 UID 和十槽状态；必须取得完整能力 0x0F。拔线重连后重新执行，不续跑。
3. 从空槽开始测试正常两遍、首遍过短、第二遍不匹配／过短；记录真实 ce 事件，检查“已受理”与“首遍有效”都不会弹完成备忘。
4. 分别在准备、首遍、第二遍、保存附近取消或断连。再次查询，核对最终状态；重学失败时不能由手机恢复旧的“已学习”标记。
