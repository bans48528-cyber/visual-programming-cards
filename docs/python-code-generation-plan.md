# 积木到 Spark AI Python 的映射与实现方案

日期：2026-09-10

本文记录对 Spark AI 参考项目的分析及代码生成方案，不代表所有映射已经实现或通过硬件测试。主任务可能正在同步开发；落地前应核对当前代码，优先复用已有生成器，不重复创建模块。

## 1. 目标与边界

将 visual-programming-cards 中的积木及参数，按执行顺序生成相同硬件使用的 Spark AI Python 方言。

- 输入：当前作品的 `program` 积木树，包括 `id`、`params`、`children`。
- 输出：可预览、导出的完整 Python 源码，以及无法生成时的明确错误。
- 生成过程使用固定规则，不依赖 AI 临时编写代码。
- 只编译程序区；暂存积木、拖动投影和主页示例缩略图不参与执行。
- Python 生成、设备上传、运行与暂停是不同层次，应分别验证。

生成代码依赖硬件的 Spark AI 运行环境。不能假设 `_motor` 等对象在普通桌面 Python、标准 MicroPython 或任意 ESP32 固件中存在。

## 3. 积木映射

下表的函数名称来自参考项目；默认参数、界面语义及执行策略仍须按第 4 节确认。代码中的 `port`、`power`、`seconds` 等是占位参数，生成时应替换为经过校验的实际值。

| 当前积木 ID | 生成方向 | 说明 |
| --- | --- | --- |
| 开始块（界面锚点） | 生成程序入口所需初始化 | 不作为普通动作重复输出 |

| `combo-turn-right` | `_motor.mov_dir_power_seconds("right", power, seconds)` | 同上 |

## 4. 必须对齐的硬件与语义

### 4.1 端口

参考方言的端口编号为 A=0、B=1、C=2、D=3、E=4、F=5、G=6、H=7。参考硬件说明中，传感器通常接 A–D，电机通常接 E–H。

分析时我们的单电机选择器使用 A–D，因此存在语义冲突。应明确选择一种策略：

1. 将电机界面端口改为真实 E–H，并对旧存档进行明确迁移。
2. 保留 A–D 作为逻辑电机名称，通过设备配置显式映射到物理端口。

不得静默将界面上的电机 A 编译为物理端口 0，也不得未经确认直接批量重写旧作品。

组合电机需要配置左右端口、配对模式与停止模式。参考本地编译器使用 E/F、模式 1，但这是参考默认值，不是所有作品的接线事实。

### 4.2 动作时间与功率

当前单电机和组合动作有时间参数，但缺少功率参数。建议先将默认运动功率、转向功率放入统一硬件配置，后续再决定是否暴露到每个积木。

参考本地编译器使用运动功率 50、转向功率 40，可作为待确认的初始方案。定时函数是否阻塞、结束后如何制动、反转与左右转向是否符合接线，都需实机验证。

### 4.3 传感器积木

建议将顺序链中的传感器积木解释为“等待条件成立，然后继续”，而不是读取一次后忽略结果。例如：

```python
while not (_ultrasion.cmp_value(3, "<", 10)):
    _os.sleep_s(0.001)
```

这里假设超声波接 D 口；最终应读取配置。灰度与外接按键同样需要明确端口。

- 超声波的严格相等可能难以稳定满足；是否增加容差需明确产品语义，不能私自改变 `==`。
- 分析时灰度参数误标为 `cm`，应改为灰度数值对应单位，而不是距离单位。
- 条件等待不是自动停止电机。如果前序动作仍在持续运行，需要根据明确的动作语义处理。

### 4.4 点阵

当前编辑器为 5×5，参考 `_matrix.show` 接收 7 个行值，每行对应 5 个像素。

可选方案：将编辑器升级为 5×7，或将现有 5×5 居中放入 5×7，上下各补一行 0。升级时应兼容旧存档，不丢失原图案。

本地编译器按 `sum(pixel[column] << column)` 编码行值。像素左右方向仍应通过不对称图案进行实机确认，避免镜像。

### 4.5 音符

界面 1–5 建议对应 `c`、`d`、`e`、`f`、`g`，默认节拍需要明确。`beats` 不应未经验证直接当作秒。

### 4.6 暂停与停止

`_os.stop_exit()` 是参考清单中的停止退出函数，不等于可恢复的暂停。

界面暂停按钮最终是“暂停后可继续”还是“停止整个程序”，需要另行确认，并核实设备控制协议。不要简单向源代码末尾追加停止语句，作为对正在运行的无限循环的外部停止方案。

## 5. 生成流程

```text
作品 program + 硬件配置
    → 数据及参数校验
    → 收集所需硬件初始化
    → 递归生成顺序链与循环体
    → 生成完整 Python 源码
    → 方言兼容校验
    → 预览 / 导出
    → 后续独立实现上传与运行
```

- 按原始积木树生成，不从 DOM、图标、参数舱文字反向解析。
- 使用完整参数值；界面的三位数字截断只影响显示。
- 循环外的后续指令必须恢复父级缩进，不能误编译进循环体。
- 初始化按需生成且去重，例如只在使用组合电机时输出配对配置。
- 以固定空格数缩进；嵌套循环计数变量应避免冲突，并验证参考转换器是否接受对应命名。
- 空循环不能输出空 Python 语句体。使用 `pass` 或短等待前，要验证目标方言与参考转换器支持情况；尤其不能让空无限循环高速空转。
- 未知积木或非法参数应返回带积木路径的错误，不静默跳过。
- 数字校验包含有限数、范围和整数约束；比较符号、端口、方向和音符使用白名单。
- 新模块应与布局、拖动、保存结构解耦。若已有生成器，应先审阅并扩展现有实现。

参考逆向转换器可用于兼容性检查，但通过转换器不等于通过硬件执行测试。`.sparkai` 导出属于可选兼容能力，不应成为网页直接生成 Python 的必要依赖。

## 6. 示例

假设左右电机接 E/F，配对模式与停止模式均为 1，功率 50，音符时值 0.25 拍。程序为：前进 1 秒、等待 1 秒、重复两次后退 0.5 秒、停止、演奏音 1。

```python
_motor.pair(4, 5, 1)
_motor.mov_set_stop_module(1)

_motor.mov_dir_power_seconds("advance", 50, 1)
_os.sleep_s(1)
for count in range(2):
    _motor.mov_dir_power_seconds("retreat", 50, 0.5)
_motor.mov_stop()
_beep.play_muic("c", 0.25)
```

这是基于参考接口的生成示例，不是已经在用户设备上验证的运行结果。运行时对象初始化、完整上传包装和执行入口应继续核实，不能随意补写普通 Python 导入语句。

## 7. 验收标准

### 生成器测试

- 每个当前积木至少一个期望源码测试，覆盖默认参数和非默认参数。
- 覆盖单电机正反转、端口映射、组合电机初始化去重。
- 覆盖空程序、空循环、多指令循环、三层嵌套和循环之后的普通指令。
- 覆盖小数时间、超过三位数的原始值、非法数字、未知端口与未知积木。
- 覆盖 5×5 旧图案适配、行编码和不对称图案。
- 暂存区与拖动投影不影响生成结果，同一份数据生成相同源码。

### 编辑器集成测试

- 修改参数、移动积木、撤销重做和重新打开作品后，源码与程序树一致。
- 生成失败指出相关积木，不允许将不完整代码当作成功结果发送。
- 桌面和手机均能查看代码与错误，生成器不改变已有作品数据。

### 实机测试

- 核对电机端口、正反转、定时结束行为、左右转向和停止模式。
- 核对传感器端口、比较条件、等待行为与主机按键。
- 核对点阵尺寸、方向、音符与节拍。
- 验证上传、运行、断连和紧急停止；无限循环必须能可靠终止。

## 8. 推荐实施顺序

1. 确认端口映射、传感器等待语义、点阵适配和默认参数。
2. 审查当前已有生成代码，复用参考接口并补齐全部积木映射。
3. 完成生成器单元测试和方言兼容检查。
4. 接入代码预览与 `.py` 导出，不依赖蓝牙连接。
5. 使用实际硬件验证后，再对接发送、运行及暂停或停止功能。
