# 当前方案更新：纯遥控编程

2026-09-29 按用户最新要求，LBS2206 由手机执行逻辑，通过无响应写入发送遥控帧。下文完整程序上传方案保留为历史记录，不再作为当前执行路径。

- 运动：前进、后退、左转、右转（秒）；持续移动（选择方向）；停止；功率 1～5 档。
- 逻辑：等待时间、有限循环，均在手机执行，不发送固件等待或循环标记。
- 默认编程功率 3 档；功率块更新后续动作，持续运动期间改变功率会重新发送当前方向。功率块本身不会启动停止中的电机。
- 按时间运动在遥控写入完成后计时，时间到发送停止；蓝牙延迟仍会影响实际机械时长。
- 持续运动延续到下一动作或停止；程序结束、用户停止会发送遥控停止。取消使未发送的旧任务失效。
- 图标与小白组合电机积木共用；LBS 独立执行器，不发送小白 C1/C2 或完整程序帧。
- 旧步数积木作为历史积木保留，不自动改单位；运行前明确要求用户替换。
- `programVerified=false` 保留；旧完整上传接口不是当前 APP 编程入口。
- 实物已确认无响应写入下最大档前进/停止；其他方向、档位及手机计时程序待实物复核。

# LBS2206 V1.02 接入状态与实物验证

依据用户提供的《LBS2206 V1.02 通信协议》《LBS2206 V1.02 产品描述》，并核对 `F:\2020\lbs2206\V1.02\电机V1.02\lbs2206` 中的接收及动作表代码。

## 当前状态

APP 已增加 LBS2206 型号、独立协议/蓝牙/执行模块、步数积木、遥控页和设备设置。小白保留原来的配置、逐条执行方式和 BLE 行为。LBS2206 的完整动作表由 APP 编排并直接编码，一次上传即由车端启动；没有编译器，也没有另行“开始”帧。

**目前不是已验证可用的手机直连版本。** `lbs2206-profile.js` 的 UUID、帧时序、安全动作数全部未填写，验证标记为 false。正式配置允许查看界面和编辑程序；Android 可扫描并只读检查 GATT；连接业务通道、遥控和上传均不能绕过验证门槛。不能把测试夹具中的 UUID、帧长度和动作数填入产品配置。

## 缺失信息

| 项目 | 需要提供或实测的内容 | 当前处理 |
| --- | --- | --- |
| BLE 模块 | 模块具体型号、固件版本、手机中心端兼容性、是否需配对/绑定 | 不从 CC2541 芯片型号推断模块协议 |
| GATT | 服务、写入、通知 UUID；Write/Write Without Response 和 Notify/Indicate 属性 | 新增只读服务发现；不套用小白 FFF0/FFF1/FFF2，不自动猜选可写特征 |
| 广播识别 | 实物名称、可确认的前缀或服务广播规则 | 支持未命名设备扫描；无已确认规则时，首次连接由用户手选；已保存默认设备按唯一标识寻找 |
| BLE 到 UART 时序 | 一次 BLE 写入在 UART 上的真实输出、内部拆分间隙、连续两帧需要的间隔，覆盖手动约 10 ms 和程序约 60 ms 空闲判帧 | 当前仅实现完整帧单次写入；不做 APP 分包、不使用 MTU 长写拼接 |
| 安全程序长度 | 固件接收/解码越界问题的修复或验证依据，以及每个已验证长度的实际接收和执行结果 | 安全动作数为空；不会用 99、120、199 或“250 条”注释推导安全上限 |
| UART 配置差异 | 小车的偶校验与遥控器串口配置差异、模块的实际波特率和校验 | 待串口抓包，APP 不发送 AT 命令调整模块 |
| 停止及状态 | 运行/空闲/上传中停止、断连停车、状态回报顺序、无序号回复的迟到行为 | 回报驱动状态；超时保持未知与上传锁定；待实物验证 |
| 运动与校准 | 五档实际速度、一步实际运动、STPL/STPR/间隔/速度参数可用范围 | 与遥控器一致使用低四位 1～5；步数不换算成厘米/角度；校准写入暂不开放 |
| 等待/固件循环 | 等待准确时长、循环标记位置/数量与组合边界 | 不生成 0x60、0x81～0x8F，一直循环隐藏 |
| 产品图片 | 整机照片或正式图标 | 使用标识小车的示意图，不当作实物照片 |

车端动作表 `RunTable[120]` 与复制函数的 199 上限不一致，接收解码另有越界风险。遥控器的 99 动作容量只描述该遥控器缓存，不能证明车端任何对应长度安全。

## 已实现的协议与交互

- 遥控：前、后、左、右、五档，松手/取消触摸/窗口失焦/关闭遥控发送停止。五档沿用原遥控器低四位 1～5，对应车端内部 2～6 档；不称其为车端 1～5 档。
- 编程：四个运动积木的参数是正整数步数；每一步展开为一个 0x10/0x20/0x40/0x50。有限循环由 APP 展开，包括嵌套循环。无程序调速、等待、固件循环标记或一直循环积木。
- 上传：生成 `{动作表}` 后进行反码配对；在分配动作数组前先计算展开长度，检查已验证动作数和编码字节数。编辑器的 100000 动作计算预算仅用于防止 APP 资源耗尽，不是设备容量。
- 单帧：本次原生实现只支持不超过 20 字节的完整写入，还必须小于配置中已实测的 `maxFrameBytes` 和当前 MTU 的载荷容量。**20 是本次实现的传输限制，不是已验证的串口或程序安全长度。** 即使动作表落在该限制内，`safeActions` 和 `programVerified` 未确认也不能发送。
- 状态：发送成功只显示等待开始；收到 `00 00 00 06` 才显示执行开始，收到 `00 00 00 0D` 显示停止，收到 `00 00 02 00` 显示完成。没有积木级进度高亮。
- 上传中、待开始、运行、待停止、状态未知均锁定重新上传。开始或停止回报在 APP 的 4 秒观察窗口内未到达，显示状态未知，不声称硬件停止。4 秒是 UI 等待策略，不是固件承诺的超时。已开始后的长程序不按估计时长假定完成。
- 停止：使用 `84 7B F5 0A`，不拿新程序包代替；切换型号销毁旧连接并取消队列。正在等停止确认时避免重发重叠停止请求；无回报进入未知后可再次尝试停止或断开。
- 维护：设备设置中提供固件版本、电压、MAC、直行/转向校准值读取。ASCII 不做反码配对。写校准、复位和单电机维护控制暂不开放；所有 AT 命令被排除。
- 数据：程序、非空草稿、最近编辑与默认 BLE 设备仍按型号保存；本地设备名称沿用现有唯一标识存储。检查 GATT 不更新默认设备，业务连接成功才更新。

## 实物接入顺序

1. 在 Android 的 LBS2206 蓝牙页扫描实物，点“检查 GATT”。该流程只做服务发现，随后断开；结果保存在 `cardModel:lbs2206:gattReport:v1`，设备设置中可查看。
2. 对照模块资料确认业务 UUID 与属性，确认通知订阅。记录模块、固件和手机版本。GATT 可写不等于已确认是业务通道。
3. 使用串口抓包检查短完整帧的 BLE→UART 输出，确认每帧内部无触发空闲结束的间隔，并确认帧间间隔。当前实现不分包；若单次写入也被模块拆成独立串口帧，需要先解决模块/固件兼容性。
4. 先验证模式切换、四方向、五档、松手停止、断连停车。确认后填写 `gattVerified / atomicFrameVerified / maxFrameBytes / frameGapMs / evidence`，才开放遥控。`frameGapMs` 必须是实测值，且大于源码的约 60 ms 最大空闲判帧值。
5. 核实或修复车端越界，再从极短程序验证接收、执行、停止及回报，逐步记录可安全接受的动作数；填写 `safeActions / programVerified`。不要直接填 99。
6. 扩展分包、等待、固件循环或校准写入时另做协议与实物验证；本次未预先启用。

- `npm run test:lbs`：反码编码、方向与速度、步数及嵌套循环展开、长度拦截、分片通知重组、回报驱动状态、停止、超时锁定，以及模拟 Android 的连接/GATT/遥控/上传链路。
- `tests/LbsFrameTest.java`：原生写入白名单、长度与反码校验、禁止 AT/固件循环/等待及未开放维护写入。

- 现有小白协议、编辑器、蓝牙、遥控、多型号迁移与取消回归测试。
