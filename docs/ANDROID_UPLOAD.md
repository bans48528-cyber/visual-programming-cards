# Android 程序发送

2026-09-14：黄色“运行”按钮使用手机内置 Pika 编译库，将当前作品写入 Spark_AI 的 **0 号槽位**，覆盖原程序并通过 BC 终包请求运行。灰色按钮取消编译或发送，并按网页版逻辑请求暂停；取消后需重新完整发送。

## 流程和边界

1. 检查连接，关闭遥控页，本机编译；发送期间禁止非零遥控按键。
2. 按网页版准备状态：已有新鲜 stop 时继续；run 或状态过期时发送 5 次 B9（间隔 80 ms），最多等待 5 秒停止上报。没有状态时发 D0 并等待 500 ms；仍无状态可继续，随后出现非 stop 状态则阻止发送。
3. 原生 `prepareUpload` 协商 MTU，请求 512，最低要求 138，以容纳 135 字节的完整数据帧。
4. `UploadGate` 校验长度、槽位文件名、Pika 文件头、128 字节中间包和剩余长度终包。依次发送 DA 文件名、AA 数据、BC 结束并运行。原生 begin 显式记录 run 模式，禁止提前 BC 或错用终包；独立 B6 仍不放行。暂停仅放行完整固定 B9 帧。
5. 每包等待校验正确的 `FD 01` 回包，再发送下一包。Android 忽略其他合法二进制回包，包括状态查询的 `FF FF`；桌面保留原 APK 兼容方式。超时不自动重传。
6. 完成后读取状态并释放发送会话。取消、后台和断连中止发送，不能视为槽位内容已完整保存。

## 验证

`tests/android-upload.spec.cjs` 覆盖正常流程、运行状态阻止、MTU 失败、状态回包不能确认文件包和取消；`tests/UploadGateTest.java` 校验原生帧顺序、长度和禁止运行命令。协议及 Android 界面回归测试通过。

真实写入脚本 `tests/spark-upload-device.spec.cjs` 必须显式提供手机序列号、设备地址及 `--overwrite-slot0-and-run`。该脚本会新建等待作品、覆盖主机槽位并运行，然后点击暂停；仅在用户已授权该槽位及运行验证时执行。

## 暂停按钮与网页一致

- 新鲜 stop：取消后续发送，不发送 D0 或 B9，避免重新启动。
- 没有状态：D0 → 等待 200 ms → 一次 B9。
- run 或过期状态：连续 5 次 B9，间隔 80 ms。
- 连接变化或后台切换中止剩余请求。B9 是硬件键模拟，提示仅表示已发请求，状态文字由主机上报决定。
- BC 终包阶段允许主机先上报 run 再返回确认，不将该状态误判为上传异常。
