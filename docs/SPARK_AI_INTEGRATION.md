# Spark AI 多型号接入（2026-09-29）

## 执行方式

型号 ID `spark-ai`。23 个原有积木使用原始端口和参数，积木 JSON → `program-codegen.js` → 手机 `CardCompiler` → Pika `.py.o` → 设备 `0.o` 槽位 → 设备运行。不是小白 C2 逐条执行，也不是 LBS2206 遥控序列。

- 型号配置：`spark-ai-model.js`。电机6、组合电机8、传感器4、逻辑3、声光2。
- 硬件适配：`spark-ai-adapter.js` 复用 `spark-protocol.js`，只接受 FD 01 文件确认；DA 文件名、128字节 AA 中间包、BC 末包并请求运行。
- Android 使用独立 `spark-ai` profile，FFF0 服务、FFF1 通知与写入。上传协商 MTU≥138，文件顺序经过 UploadGate 校验。小白 C2 不在该 profile 放行。
- 手机编译器恢复插件注册、独立非导出编译进程、JNI 库打包和构建。共享生成器仍与原29组基准源码完全一致。
- 遥控使用 Spark 原始 C1 顺序：方向、A/B/X/Y/L/R。小白仍使用自己的 Y/A/X/B/R/L 顺序，肩键规则互不套用。

## 状态和取消

编译/上传中不能重复运行；上传后根据设备 run/stop 回报显示状态，未提供逐块执行位置。stop 回报只表示停止，不推断正常完成原因。B9 是主机按键模拟，已停止时不重复发送，以免切回运行。

上传中取消、异常或连接变化后不会继续发送；由于 ACK 没有序号，中断文件上传后要求重新连接，避免旧 ACK 确认新包。切型号会取消编译并停止旧连接；编译迟到结果被丢弃。

上传覆盖主机0号程序槽位。手机端256 KiB输出限制是桥接限制，不能当作设备安全程序容量。设备上传/运行/停止仍需要当前硬件复测。

## 界面和数据

共享蓝牙页面与3秒首次/10秒默认设备自动连接规则，仅匹配广播名 Spark_AI。默认蓝牙设备、草稿、作品按型号保存，自定义蓝牙名称仍共用本地名称表。

旧 `cardProjectsV1` / `cardActiveProjectV1`，或独立工作区 `visualProgramV2/V1`，一次性迁移到 Spark AI；保留旧键，不覆盖已有分型号作品。小白原迁移独立保留。

型号图使用通用点阵标识，并非产品实物图片。提供产品图片后可替换。网页用于选择型号和编辑预览，不连接硬件或依赖电脑编译服务器。
