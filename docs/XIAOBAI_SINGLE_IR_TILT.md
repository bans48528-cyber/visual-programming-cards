# 单路红外与等待倾倒手机接口

协议依据：主控工程 `LBS-XIAOBAI-AI/docs/single_ir_accel_protocol.txt`（2026-10-29）。

手机已通过软件模拟及生产 Java 帧校验器进行回归；新版主控编译结果和新板的方向、振动稳定性、传感器掉线、心跳停机均需硬件线程及用户实测确认。

`CardBluetooth.remoteConnection().readTilt()` 仅在已进入编程模式时显式查询状态，不参与积木完成判定。UI 继续只有单个红外等待条件，无三通道传感器展示。

软件回归入口：`npm run test:tilt`（先运行 `npm run build:web`，APP 流程测试需要本机 4173 服务）。专用 Node 用例覆盖四方向及非法参数、真实 DONE、连续同向等待、300ms 心跳、不轮询、停止/断连/模式切换/传感器故障、READ_TILT 数据校验，以及序号回绕时未发送请求不能接收旧 DONE。生产 `ProgramFrame` 校验器覆盖 2725 项合法/非法帧。

请求只有在真正开始写入后才允许接收反馈；该标记在调用传输前同步设置，兼容快速或同步到达的真实 DONE。

```text
小白新版硬件：单红外与SC7A20HTR倾倒等待（2026-10-29）

引脚/电路
PA0：电池分压ADC；PA1：唯一红外ADC；内部VREFINT保留用于电压补偿。
PA2：SC7A20HTR SCL；PA3：SC7A20HTR SDA，采用开漏软件I2C。
这对接线与MCU硬件I2C复用方向相反，不能直接配置硬件I2C AF。
CS须置为I2C模式；SA0决定0x18/0x19，固件自动探测两地址；SCL/SDA须有适当外部上拉。
用户已确认安装轴向：+X主机前方、+Y左方、+Z上方。
方向/阈值仍需新板实测核对，尤其是运动与电机振动下的表现。

红外兼容
新版只存在一枚PA1红外传感器。旧通道编号0/1/2均作为它的兼容别名。
WAIT_IR 0x30格式保持不变，手机现有[1,cmp,threshold]继续读取PA1。
READ_IR 0x31、QUERY_STATUS中的旧红外三槽都返回同一PA1归一化值；
D3 IR_CHANGE三槽/位图相应镜像。它们不再代表独立的左、中、右传感器。
手机新UI只显示单路红外，不应把镜像画成三枚传感器。
感应模式四种玩法和语音红外互动也统一使用PA1。

BLE外壳
仍用17字节C2/D2/D3、原地址和校验；多字节整数规则不变。
本扩展不占用ASR自学习的caps字段，不改变旧操作码和固定词条。

姿态枚举
0未知/不稳定，1水平正放，2向前倾倒，3向后倾倒，4向左倾倒，
5向右倾倒，6倒置。驱动仅在静态加速度可信且姿态稳定后报告方向。
未知但通信正常和传感器缺失/读取失败是不同状态。

C2 0x32 WAIT_TILT
args[0]：目标方向2/3/4/5，args[1..7]必须为0。
手机方向映射forward=2, backward=3, left=4, right=5。
只允许编程模式。同一时刻沿用单个等待任务；QUERY_STATUS任务码新增6。
等待期间手机沿用300ms心跳。读状态和心跳不取消等待。
加速度数据经稳定判断，匹配后再做连续采样确认才发D2(seq,0x32,OK)。
沿用DONE立即发送并每200ms重发的机制；手机只推进当前编号一次。
语义是等待指定稳定姿态：若执行积木时已经处于该姿态，也可以满足条件；
连续两个同方向积木不要求回正后重新倾倒，与语音口令新发声的语义不同。
停止、断连、模式切换、心跳超时均取消等待并按原有会话流程刹停，不能当作成功。

C2 0x33 READ_TILT
args[0..7]必须为0，只允许编程模式；查询不打断学习/等待任务。
D2 data[0]：姿态0..6；data[1]：传感器有新鲜有效采样1/不可用0；
data[2]：物理红外数量，固定1；data[3..6]保留0。
data[1]=1而data[0]=0表示正在运动、姿态未稳定等情况，可继续等待。
不可用时result=0x0A，data[0..6]全部为0，不使用上一次缓存冒充当前姿态。

错误/故障
新增D2 result=0x0A SENSOR_UNAVAILABLE。
开始等待时传感器不可用：拒绝，刹停，发对应D2错误与D3 PROGRAM_ABORT。
等待中传感器掉线/数据过期：终止等待，刹停，发对应D2错误和D3中止，绝不发成功DONE。
D3 PROGRAM_ABORT data0新增原因7=传感器故障，data1仍为模式4；data7=任务码6。
QUERY_STATUS故障低半字节bit3表示加速度传感器故障；成功读取/重新开始等待后清除。
旧固件对0x32/0x33返回BAD_OPCODE；手机必须提示需更新主控，不可自行模拟完成。

验收范围
软件回归需覆盖PA2/PA3不进ADC、VREFINT索引、电池换算、单红外四玩法、
四方向稳定/抖动/振动/自由落体、错误身份/缺失芯片/NACK/总线占用、
状态查询、保留字节校验、等待取消/断连/心跳、回绕和DONE去重。
编译通过不等于新硬件验收通过。更新目标是PY32主控，ASRPRO工程无需因此更新。

```
